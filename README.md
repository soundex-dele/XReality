# XReality Desktop

Windows x64 的 Unity 双入口桌面应用：猫咪陪伴房间 / 真人面捕直播间。两者通过单场景切换互斥运行。没有云服务、账号、推流或麦克风采集。

## 启动与构建

1. 准备 Windows x64、Python 3.9+、已激活的 Unity **6000.3.10f1**（Windows Standalone Mono 支持）。关闭同一工程的其他编辑器实例后再做批量构建。
2. 在仓库根目录执行 `python Tools/project.py setup`。首次克隆会下载官方 homuler 0.16.3 UPM 发布包（约 290 MB，含原生 DLL），验证 SHA-256 后才安装。不要以 Git 源码包替代。发布包不捆绑模型，直播端首次使用可从应用内下载，安装后可离线。若下载需要代理，可为当前终端设置 `HTTPS_PROXY`。
3. 用 Unity Hub 打开本目录。编辑器导入完成后会从 `StudioProject` 和 `StudioArt` 自动生成 **Home / PetRoom / LiveStudio** 三个可编辑场景、URP 资产、六个动画状态和角色绑定。若未自动打开，可用菜单 **XReality → Prepare project**，打开 Generated 下的 Home 场景，点击 Play。批量构建也会执行相同准备步骤。
4. `python Tools/project.py build --smoke` 编译 Windows x64 并运行无摄像头的打包程序检查。非默认安装目录使用 `--unity "D:\你的目录\Editor\Unity.exe"`。产物是 `Builds/Windows-0.3.20/` **整个目录**，不是单独复制 exe。日志在 `Builds/unity-build.log`、`Builds/player-smoke.log`。

Generated 是生成目录，不提交；已有场景不被 Prepare 覆盖。需要长期保留的美术修改请同步回生成器或转为独立的版本控制资产。URP 锁定 17.3.0；Unity/插件组合仍须在目标电脑验证，勿把版本固定解读为兼容性认证。

## 操作

- **猫咪**：点猫或用“摸摸它”；拖动毛线球或点击“滚动毛线球”。清醒时歪头蹭手；困倦时身体下沉、闭眼，仅动耳回应。拖球后先转头，再追过去。名字和亲密度只在本机 PlayerPrefs 保存；离线时间不参与计算。首页设置音量。
- **直播**：首次下载并校验模型，随后点击切换设备、启用、正视镜头校准。控制面板只显示设备名称和状态，不展示真人。F8 切换纯绿幕，Esc 返回预览。程序后台继续运行；关闭相机或回首页释放设备。启动无画面约 6 秒后可重试。嘴形来自实际面部运动，与声音无关。
- **隐私**：相机只在用户手动启用后打开。内存中的颜色缓冲区进入本机 CPU 检测，帧不上传、不写入日志/文件、不作为渲染材质。切换场景和禁用组件都会关闭采集。

## 验证分层

| 检查 | 操作与通过条件 |
|---|---|
| 不用 Unity 的本机检查 | `python Tests/check_local.py`：哈希校验；编译实际 C# 宠物状态机，验证反复点击、不同时态摸头、先观察再追赶和到达；从锁定的 Win64 原生 DLL 对真实 detector 子模型执行一次空白输入 CPU 推理。不是完整 Face Landmarker 或实机面捕测试。 |
| 无窗口截图 | 安装工程依赖后运行 `python Tools/project.py screenshots --unity <Unity.exe>`。批处理下用 URP 渲染至纹理，不运行打包程序、不请求摄像头、不下载测试素材。`Builds/QA-Offscreen` 中包含 1280×720 场景、宠物姿势与表情对照；同机位比对猫的休息/关注/追逐以及化身左右眼和嘴部区域。只验证 3D 场景与已绑定表情的静态网格，不包含控制面板、运行时面捕或交互。 |
| 解包程序离屏截图 | `python Tools/project.py packaged-screenshots`：复核便携包哈希，解压到临时目录，用批处理模式让包内程序离屏渲染 1280×720 截图，监测是否出现可见窗口。直播初始控制面板本身参与渲染，并检查绿幕无面板、退出绿幕后面板恢复；不启用输入模块或摄像头。可加 `--offline-tracking`，用现有的哈希固定 QA 模型和公开人像驱动纯绿幕化身，不自动下载、不输出真人图，并在隔离目录截图验证模型缺失、校验失败、校验成功但无摄像头三种状态；加 `--pet-interaction` 可用临时测试档生成实际抚摸、追球、重启恢复截图，不模拟鼠标或键盘。`--retry-screenshots` 在隔离批处理模式注入连接错误，截图验证自动重试、取消及退回手动安装，不访问网络。显式加 `--download-screenshots` 时另外访问官方模型地址，在临时目录截图验证下载、取消、重试和校验安装。它们不替代实际摄像头、输入设备或另一台电脑兼容性验收。 |
| Windows Player 冒烟 | `build --smoke`：打包程序中往返三个场景，检查隔离、动画、相机默认关闭；用公开测试人像和空白图验证完整 Face Landmarker VIDEO 图；启动两个独立进程验证宠物存档。首次会获取经过哈希固定的本地 QA 文件（不会随应用分发）。 |
| 目标机人工验证 | 冷启动无相机也能养宠；改名/摸头后重启保留；摄像头被占用后释放并重试；正视校准、转头、左右单眨眼、说话停顿、离镜/再入镜；绿幕不出现 UI、错误文字和真人图；回首页能立即由其他应用使用相机。窗口切后台也需保持更新。 |
| 性能 | 1280×720、目标 30 FPS；用目标机实际启用面捕，持续运行 30 分钟。记录帧时间、内存和设备型号；目标值不是已达成的实测结果。无需检查第三方录制软件。 |

内置猫、化身、动作、材质与提示音均由本项目代码生成，未采用外部角色模型。第三方组件和模型来源见随应用打包的 StreamingAssets/Notices。


[便携发布与验收清单](RELEASE.md)：`build --portable` 生成不启动应用的便携预览 ZIP；`build --candidate --verify-download` 则会打开验收 ZIP 的解压副本验证实机运行与下载。
